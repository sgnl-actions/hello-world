Hello World example action for SGNL's CAEP Hub. Creates personalized greetings in 10 languages.

## Overview

This action demonstrates the standard pattern for SGNL JavaScript actions:
- Input validation with clear error messages
- Multi-language support (English, Spanish, French, German, Italian, Portuguese, Japanese, Chinese, Russian, Arabic)
- Error recovery handler with English fallback
- Graceful halt handler

## Prerequisites

- Node.js >= 20
- npm

## Configuration

### Inputs

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `first_name` | text | Yes | First name of the person to greet |
| `last_name` | text | Yes | Last name of the person to greet |
| `language` | text | No | Language code (en, es, fr, de, it, pt, ja, zh, ru, ar). Random if omitted. |

### Outputs

| Name | Type | Description |
|------|------|-------------|
| `message` | text | The personalized greeting |
| `language` | text | The language that was used |
| `processed_at` | datetime | When the operation completed (ISO 8601) |

## Usage

### Example Job Request

```json
{
  "job_request": {
    "name": "greet-user",
    "type": "nodejs-22",
    "script": {
      "repository": "github.com/sgnl-actions/hello-world@v1.0.0",
      "type": "nodejs"
    },
    "script_inputs": {
      "first_name": "John",
      "last_name": "Doe",
      "language": "es"
    }
  }
}
```

### Example Response

```json
{
  "message": "Hola Mundo, John Doe!",
  "language": "es",
  "processed_at": "2026-02-10T12:00:00.000Z"
}
```

- `tests/script.test.js` — Unit tests
- `metadata.yaml` — Action inputs/outputs/secrets ([schema](https://github.com/sgnl-actions/schemas/blob/main/metadata.schema.json))
- `dist/index.js` — Built CommonJS bundle (generated by `npm run build`)
- `eslint.config.mjs` — ESLint flat config
- `rollup.config.mjs` — Rollup build configuration

### Editor Setup

The `metadata.yaml` file includes a `yaml-language-server` directive that enables real-time schema validation and autocomplete in supported editors.

**VS Code**: Install the [YAML extension](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml) by Red Hat. Validation activates automatically via the comment at the top of `metadata.yaml`:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/sgnl-actions/schemas/main/metadata.schema.json
```

**IntelliJ / WebStorm**: Built-in YAML support recognizes the same directive.

### Releasing

Releases are created via the **Release** workflow in the GitHub Actions tab:

1. Merge your changes to `main`
2. Go to **Actions** > **Release** > **Run workflow**
3. Select the bump level (`patch`, `minor`, or `major`)
4. The workflow runs the full CI gate, computes the next version from the latest tag, tags HEAD, and creates a GitHub Release

Pin actions to a specific tag in job requests (e.g., `@v1.0.0`). Floating version tags are not used.

## Error Handling

| Scenario | Behavior |
|----------|----------|
| Missing `first_name` or `last_name` | Throws error (retryable by default) |
| Unsupported language code | Throws error (retryable by default) |
| Language/greeting related error | Error handler recovers with English fallback |
| Other errors | Error handler re-throws as fatal (no retry) |

## Security Considerations

- No external API calls — this action is self-contained
- No secrets required
- Input parameters are used directly in string interpolation (safe for greeting messages)

## Troubleshooting

| Problem | Solution |
|---------|----------|
| `Missing required parameter` error | Ensure both `first_name` and `last_name` are provided in `script_inputs` |
| `Unsupported language` error | Use one of: en, es, fr, de, it, pt, ja, zh, ru, ar |
| Build fails | Run `npm install` then `npm run build` |
| Tests fail after changes | Run `npm run lint:fix` to auto-format, then re-run tests |
